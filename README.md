# SW-Watch — Severe Weather Watch 劇烈天氣監控平台

整合雷達回波、衛星雲圖（真實色／可見光／水氣／紅外線）、測站觀測、海象（浮標站、潮位站）、雨量圖、ECMWF 與氣象署 WRF 3 km 預報（台灣附近 84 小時）與颱風（官方＋系集）預測路徑的網頁監控平台，所有圖層都可以選擇歷史時間。

- 資料處理：`pipeline/`（Python，本機或樹莓派排程執行，輸出靜態檔到 `data/`）
- 前端：`web/`（JS + MapLibre GL JS；衛星雲圖、ECMWF 預報（含海浪）、風場／海浪動畫、雷達回波、測站、氣象署颱風路徑、系集路徑、時間軸、同步切換）
- 部署（排程電腦 + Cloudflare R2 + GitHub Pages）：[部署說明.md](部署說明.md)
- 設計與進度：[設計log.md](設計log.md)

## 執行

```bash
pip install -r requirements.txt
cp .env.example .env          # 填入氣象資料開放平臺授權碼 CWA_KEY（與 R2 金鑰，見部署說明）
python -m pipeline.scheduler --once   # 各資料抓一次
python -m pipeline.scheduler          # 常駐排程
```

本機看網頁（在專案根目錄）：

```bash
python -m http.server 8765
# 瀏覽器開 http://127.0.0.1:8765/web/
```

## 颱風／豪雨事件一鍵產出（`pipeline.event_report`）

颱風或豪雨過後，執行一行指令，就會產生統計圖表、縮時影片和 YouTube 用的標題說明：

```bash
pip install matplotlib imageio-ffmpeg openpyxl pyshp
# 颱風
python -m pipeline.event_report --kind typhoon --name 薔琵颱風 --start "2026-10-22 00:00" --end "2026-10-24 20:00"
# 豪雨
python -m pipeline.event_report --kind rain --name 1025豪雨 --start "2026-10-25 00:00" --end "2026-10-26 12:00"
```

- **時間**：都是台灣時間。`--end` 省略 = 最新一筆測站快照。
- **`--kind`、`--name` 必填**：事件種類和名稱自己給，名稱會用在標題和資料夾名稱。
  - `typhoon`：做 6 支影片（雷達、雷達+颱風、衛星真實色+颱風、衛星日夜+颱風、颱風+測站陣風、颱風+測站平均風）。總結先列風，再附上期間內中心進入本島 500 km 內的颱風生命史。
  - `rain`：做 3 支影片（雷達、衛星真實色、衛星日夜），總結先列雨量。
  - 衛星只保留 5 天。超過 5 天才做影片的話，要先用 `event_archive --satellite` 存起來。
- **兩種事件的總結都有**：
  - 最大陣風、最大平均風。
  - 總累積雨量。
  - 最大時雨量，以及 3、6、12、24 小時雨量。
  - 達到氣象署雨量分級的站數。
- **短時雨量的時間窗**：只算整段都在期間內的時間窗。所以事件期間短於 24 小時，就沒有 24 小時雨量。
- **輸出**：全部放在 `charts/{起}_{迄}_{名稱}/`。

| 檔案 | 內容 |
|---|---|
| `rain_total.png`、`rain_total_station.png` | 總累積雨量（內插圖、測站點） |
| `wind_max.png`、`gust_max.png` | 最大平均風、最大陣風 |
| `rain_total.csv`、`wind_max.csv`、`rain_max.csv` | 各站數值（`rain_max` 是最大時雨量、3、6、12、24 小時雨量） |
| `county_*.csv`、`county_stats.xlsx` | 各縣市最大值（總雨量、平均風、陣風、時雨量、3、6、12、24 小時雨量） |
| `*.mp4` | 縮時影片 |
| `summary.txt` | 事件總結：颱風生命史與最接近台灣的時間、各項排行、達氣象署雨量分級的站數 |
| `youtube.txt` | 每支影片的標題＋說明（含圖例、雷達缺漏時段、事件總結），可直接貼上 |

其他參數：
- `--videos radar,radar_ty,tc,tc_ty,sat,sat_ty,gust,wind`：指定要做哪幾支影片。`tc` 是衛星真實色，`sat` 是衛星日夜（真實色轉灰階），`_ty` 再加颱風路徑。
- `--no-video`：只做統計和摘要，幾分鐘就跑完。
- `--top 6`：排行列幾名。
- `--fps 8`、`--local`、`--shp`：同 `radar_video`。

執行時要注意：
- 4 支三天的影片要跑比較久，而且要在前景執行。
- `summary.txt` 是自動整理的即時資料，數值異常的測站（例如陣風特別高）和是否登陸，請先對照氣象署的報告。

只要其中一部分，也可以分開執行：
- 統計圖表：`python -m pipeline.event_stats --start ... [--end ...]`，輸出到 `charts/{起}_{迄}/`。
- 單支影片：用下面的 `radar_video`。

## 事件觀測資料歸檔（`pipeline.event_archive`）

排程的清理規則會刪掉舊資料，本機和 R2 都一樣：測站、雷達、雨量等資料只留 `KEEP_DAYS` 天（預設 10 天），超過就全部刪除；衛星雲圖只留 `SAT_KEEP_DAYS` 天（預設 5 天）。事件結束後要在期限內歸檔。要永久保留某個事件的觀測資料，請手動執行：

```bash
python -m pipeline.event_archive --name 薔琵颱風 --start "2026-10-22 00:00" --end "2026-10-24 20:00" [--web] [--satellite]
```

| 存什麼 | 內容 | 三天約多大 |
|---|---|---|
| 預設 | 測站 10 分鐘快照、雷達整合回波、氣象署雨量格點、颱風路徑與颱風消息（颱風往前多存一天）、海象每小時快照 | 約 100 MB |
| `--web` | 網頁圖層用的衍生資料：測站累積 `stations/agg_*`、雨量內插 `rain/idw/*` | 再加約 200 MB |
| `--satellite` | 衛星真實色（WebP）與 B03（0.02°）／B07／B08／B13 格點；真實色上線前的時段另存 0.01° 的舊 B03。只保留 5 天，事件結束後要盡快執行 | 約 2–3 GB |

- **壓縮**：雷達、雨量、衛星、測站累積這幾種原本就是壓縮檔，照原樣存。測站快照和颱風路徑原本沒壓縮，歸檔時會壓縮成 `.json.gz`，測站快照約剩原本的 1/4。

- **存放位置**：`archive/{起}_{迄}_{名稱}/`，目錄結構同 `data/`，每層有自己的 `index.json`，另有一個 `event.json` 記錄事件資訊。
  - 這個資料夾不進 git，`cleanup` 也不會動到。
- **資料來源**：本機 `data/` 有的直接複製，沒有的從 R2 下載。已經存過的檔會跳過，中斷後重跑會接著做。
- **上傳 R2**：`.env` 有 R2 金鑰時，會另外上傳到 R2 的 `events/{起}_{迄}_{名稱}/`，並更新 `events/index.json`。
  - 加 `--no-upload` 就不上傳。
  - 沒有金鑰的電腦只會存在本機。到排程電腦再執行一次同樣的指令，就會補上傳。
- **事後重做**：`event_stats`、`radar_video`、`event_report` 都會自動讀 `archive/`。原始資料被清掉後，還是能重做統計和影片，可以加 `--local` 只用本機資料。

## 氣象署 WRF 3 km（模式預報）

`pipeline/fetch_wrf.py`（排程每 10 分檢查）抓氣象署區域模式 3 公里（開放資料 M-A0064）：降雨、2 m 溫度、10 m 風、海平面氣壓，0–84 小時每 6 小時。
- 來源是 cwaopendata S3 的公開網址（不計會員次數）。每個時刻一個 GRIB2 約 180 MB，用 HTTP Range 只抓需要的 5 欄，一報約 175 MB、半分鐘。
- S3 只保留最新一報（起報後約 5–6 小時上完），漏抓就補不回來。
- Lambert 3 km 網格內插成 0.03° 經緯度，範圍同 ECMWF；檔案格式同 `data/ecmwf`，存 `data/wrf/`，保留天數同 ECMWF。
- 網頁「模式預報」圖層的「模式」選 ECMWF 或氣象署 WRF 3 km。3 km 沒有陣風、海浪，雨量最短 6 小時。風場動畫跟著選的模式；海浪動畫只用 ECMWF。

## 氣象署海浪模式（模式預報）

`pipeline/fetch_cwa_wave.py`（排程每 10 分檢查）抓氣象署海浪模式（開放資料 F-A0020-001）：浪高、浪向（來向）、平均週期，0.1°、逐時 0–168 小時，一天 4 報。
- 來源是 cwaopendata S3 的 zip（約 58 MB，內含 169 時刻 × 3 變數的 XML），先比對 ETag，沒更新不下載。S3 只保留最新一報。
- 只留和 ECMWF 範圍重疊的 115–126°E、17–28°N（資料最東到 126°E），每報約 1.5 MB；保留天數同 ECMWF。
- 檔案的欄位說明是亂碼：浪向和 ECMWF 平均波向比對是來向；週期平均比 ECMWF 尖峰週期短約 1.6 秒，所以標「平均週期」。
- 網頁「模式預報」的「模式」選「氣象署海浪」：變數有浪高、平均週期，時刻逐時到 7 天；海岸處理同 ECMWF 海浪。選它時海浪動畫改用氣象署海浪，風場動畫用 ECMWF。

## ECMWF 海浪、風場／海浪動畫（網頁）

ECMWF 預報除了大氣，也抓海浪模式（同 0.1° 網格；陸地沒有值）：`swh` 示性波高、`mwd` 平均波向、`pp1d` 尖峰週期。網頁 ECMWF「變數」可選「浪高」（色階和浪級同海象圖層）、「尖峰週期」，箭頭畫浪前進方向。海浪是 2026-10-28 才加的，之前的起報沒有海浪檔，選浪高會顯示無資料。

風場動畫、海浪動畫都用 ECMWF 的檔，疊在所有圖層上，不需要另外抓資料：
- 風場動畫：10 m 風（`u10`、`v10`）的流動粒子，留尾跡。
- 海浪動畫：往浪前進方向移動的波峰弧線；弧越長浪越高、移動越快週期越長。
- 海岸：海浪模式近岸約 10 公里內沒有值，網頁把外海的值往陸地外推 3 格，再用底圖陸地（`land.json`）裁切，色塊和波峰都貼齊海岸線；點擊外推區會標「近岸外推」（不是真的近岸浪況）。
- 時間：ECMWF 圖層開著就跟它顯示的預報時刻；沒開就跟時間軸（取時間之前最近一報，在前後兩個預報時刻之間內插），所以看雷達、衛星的過去或現在時，顯示的是預報，不是觀測。
- 範圍：只有 ECMWF 範圍（115–130°E、17–28°N）。
- 選項：顏色（白、黑、依蒲福風級／依浪高）、密度。淺色底圖用白色看不清楚時改黑色。滑鼠移到地圖上會顯示風向風速、浪高（浪級）來向週期；地圖擷取會一起擷取當下的粒子。

## 海象（浮標站、潮位站）

資料來源是氣象署 O-B0075-001「海象監測資料－48 小時浮標站與潮位站海況監測資料」，每小時一筆，站名和座標來自 O-B0076-001。

- **排程**：每小時整點後第 5–55 分，每 5 分檢查一次，抓到新的一小時就停。
  - 平常只抓最近 4 小時（約幾十 KB）。
  - 本機沒有資料或中斷超過 3 小時，就抓整份 48 小時把缺的補齊。
  - 這個產品只能用 REST API，每次檢查都算一次會員次數，一天約 100–200 次。
  - 寫入時是**合併**：同一個整點有新資料時，只更新有回傳的站，沒回傳的站保留原值。
  - 修復／補歷史：`python -m pipeline.fetch_marine --repair`，用 30 天資料（O-B0075-002，約 26 MB，大約晚一天）加 48 小時資料，重建最近 `KEEP_DAYS` 天的快照。要在排程電腦執行，才會上傳 R2。
- **輸出**：
  - `data/marine/{時間}.json`：每小時一個快照，一個約 10 KB，跟測站一樣保留 `KEEP_DAYS` 天。
  - `data/marine/recent.json.gz`：近 10 天（`KEEP_DAYS`）各站時序，給網頁資訊卡畫圖，壓縮後約 130 KB。
- **網頁「海象（浮標／潮位）」圖層**：
  - 可選浪高、波浪週期、潮高、海溫、風速、最大陣風、海流、氣溫、氣壓。
  - 站種可勾選：◆ 浮標（含浮球式波浪站）、■ 潮位站、⬢ 岸邊氣象站。變數分「海況」和「海上氣象」兩組。
  - 和地面測站的區隔：海上符號一律藍框，數值藍色斜體；形狀代表站種。
  - 海上氣象（風速、陣風、氣溫、氣壓）：色階和地面測站相同，方便比較。風速用和地面相同的箭頭，只是加藍框。
  - 海況專用符號：浪高 = 寬箭頭（指向浪前進方向，浪越高越大）；潮高 = ▲ 漲潮／▼ 退潮；海流 = 細長箭頭（指向流去方向，越快越大）。
  - 浪高依浪級分色：小浪 1–2 m、中浪 2–3 m、大浪 3–6 m、巨浪 6 m 以上。地圖數值旁和資訊卡會標出浪級。
  - 「顯示」可選當下值、過去最大、過去最小（1–72 小時或自訂區段），和測站一樣。最大／最小在地圖數值後標發生時間（@10/23 22:00），浪、風、海流的箭頭用發生那一小時的方向。資料每小時一筆，所以最大／最小是逐時觀測裡的最大／最小。
  - 同步模式顯示時間軸所在的整點。點站會開資訊卡，看當下各項觀測和折線圖，時段可選 6 小時到 10 天（同測站資訊卡，時間軸拉到圖外時圖會跟著移）；浪高圖上有浪級分界虛線。
- **潮高基準**：本島潮位站是臺灣高程基準（基隆平均海水面），離島和海上觀測樁是當地平均海水面，兩者不能直接比較。

## 衛星雲圖（`pipeline.fetch_satellite`）

Himawari-9 全盤資料從 AWS 下載（免金鑰），裁成 105–155°E、5–35°N，每 10 分鐘一次。

| 產品 | 資料夾 | 內容 | 網頁頻道 |
|---|---|---|---|
| 紅外線 | `satellite/B13`、`B07`、`B08` | 0.02° 數值格點，24 小時 | B13、B07、B08、夜間低雲／霧 |
| 真實色 | `satellite/TC` | 0.01° WebP 圖片，24 小時（見 `pipeline/truecolor.py`） | 真實色、日夜（同一張轉灰階） |
| 可見光 | `satellite/B03_2km` | B03 0.02° 數值格點，白天 | B03 可見光（有滑鼠讀值） |

- **真實色做法**：
  1. 白天用 B03 當紅、B02 混 15% B04 當綠、B01 當藍。
  2. 除以太陽天頂角的 cos 值做亮度補償，天頂角 80° 以上不再放大。
  3. 扣掉大氣的 Rayleigh 散射（pyspectral），太陽天頂角 80°–88° 之間逐漸減弱（80° 以前全額，否則晨昏會出現藍帶）。
  4. 套用暗部拉亮曲線（不另外銳化，網頁上看比較自然）。
  5. 夜間是 B07 短波紅外灰階（冷雲頂改用 B13），太陽仰角 0°–10° 之間漸變。
- **下載量**：白天時次要下載 B01–B04，每次約 220 MB；夜間只用已存的 B07／B13，不用下載。
- **舊資料**：0.01° 的 `satellite/B03` 已停止產生，保留到過期自動清掉。
- **補抓**：`python -m pipeline.fetch_satellite --start 202610230000 --end 202610231200 --bands B07,B13,TC`（UTC）。真實色要該時次已有 B07，所以要一起列。
## 縮時影片（`pipeline.radar_video`）

把一段期間的資料做成縮時 MP4，每 10 分鐘一格。可以做這三種：
- **雷達整合回波**
- **衛星雲圖**：真實色或日夜灰階
- **颱風路徑與測站風**

```bash
pip install matplotlib imageio-ffmpeg     # imageio-ffmpeg 內含 ffmpeg
```

### 常用指令

時間都是台灣時間，`--end` 省略就做到最新一筆。

```bash
# 雷達回波
python -m pipeline.radar_video --start "2026-10-22 00:00" --end "2026-10-24 20:00"
# 雷達 + 颱風路徑與暴風圈
python -m pipeline.radar_video --start "2026-10-22 00:00" --end "2026-10-24 20:00" --typhoon

# 衛星真實色（白天彩色、夜間紅外線）+ 颱風路徑
python -m pipeline.radar_video --start "2026-10-22 00:00" --end "2026-10-24 20:00" --tc --typhoon
# 衛星真實色，自訂較大範圍、不畫颱風
python -m pipeline.radar_video --start "2026-10-22 00:00" --end "2026-10-24 20:00" --tc --extent 110 134 14 32
# 衛星日夜（真實色轉灰階）+ 颱風路徑
python -m pipeline.radar_video --start "2026-10-22 00:00" --end "2026-10-24 20:00" --sat --typhoon

# 不畫雷達：颱風 + 測站平均風（加 --gust 改陣風）
python -m pipeline.radar_video --start "2026-10-22 00:00" --end "2026-10-24 20:00" --no-radar --typhoon --wind [--gust]

# 只輸出一張 PNG 先看畫面（給時間 = 那個時間或之前最近一格；省略 = 最新一格）
python -m pipeline.radar_video --preview "2026-10-23 14:00" --tc --extent 110 134 14 32
```

### 參數

| 參數 | 說明 |
|---|---|
| `--start` / `--end` | 台灣時間 `YYYY-MM-DD HH:MM`。`--end` 省略 = 最新一筆。 |
| `--preview [時間]` | 只輸出一張 PNG，不做影片。可以加任何其他參數一起看效果。 |
| `--fps` | 每秒格數，預設 8（三天約 50 秒）。 |
| `--gif` | 另外輸出 GIF。 |
| `--typhoon` | 疊加颱風路徑與暴風圈。 |
| `--wind` | 疊加測站平均風；加 `--gust` 改畫陣風。 |
| `--no-radar` | 不畫雷達，畫面放大到台灣本島，時間改用測站快照。 |
| `--tc` | 改畫衛星真實色（同網頁「真實色」）。 |
| `--sat` | 改畫衛星日夜：真實色轉灰階（同網頁「日夜」）。 |
| `--extent 西 東 南 北` | 只對 `--tc`、`--sat` 有效：畫面範圍（經緯度）。預設 116.1–126.6°E、20.3–27.5°N，最大到衛星範圍 105–155°E、5–35°N。 |
| `--local` | 只用本機資料，不從 R2 下載。 |
| `--shp` | `TWN_CITY` 所在資料夾，預設 `shp/`。 |

### 輸出檔名

輸出到 `charts/radar/`，檔名是 `{種類}_{開始}_{結束}{後綴}.mp4`，預覽則是 `{種類}_{時間}{後綴}.png`。

| 種類 | 什麼時候 |
|---|---|
| `radar_` | 雷達 |
| `tc_` | `--tc` |
| `sat_` | `--sat` |
| `station_` | `--no-radar` |

| 後綴 | 什麼時候 |
|---|---|
| `_wide` | 有給 `--extent` |
| `_ty` | `--typhoon` |
| `_wind` | `--wind` |
| `_gust` | `--wind --gust` |

例：`tc_202610220000_202610242000_wide_ty.mp4`

### 畫面

- **大小**：4:3（1600×1200）。範圍的長寬比不同時，會自動往外補成 4:3。
- **標題**：左上角有標題、時間（台灣時間）和資料來源。
- **底圖**：Natural Earth 陸地，加上 `shp/TWN_CITY` 縣市界（內政部，網頁底圖也用同一份）。
- **雷達**：色階同網頁，畫面上不放色階，< 0 dBZ 不畫。
- **衛星**：雲圖蓋住陸地，海岸和縣市界改成淡黃色畫在上面。
  - 真實色是白天彩色、夜間 B07／B13 紅外線灰階，太陽仰角 0°–10° 之間漸變。
  - 每天 10:40、22:40（台灣時間）衛星固定維護，沒有資料。

### 颱風（`--typhoon`）
- 路徑只畫氣象署實際定位：黑線，每個定位一點，定位之間不內插。
- 紅點是當下的颱風中心。
- 黃圈、紅圈是 7 級、10 級暴風圈，取平均半徑的正圓，只畫外框。
- 不畫預報路徑。

### 測站風（`--wind`）
- 箭頭指向風吹去的方向，顏色和長度依蒲福風級，畫面底部有 0–17 級的橫式色階。
- 靜風或沒有風向畫成小圓點。
- 只畫觀測時間在畫面時間前 60 分鐘內的測站，整點那格也包含前一小時的觀測。
- 不含日本氣象廳測站。

### 資料從哪裡來、要注意什麼

- **讀取順序**：本機 `data/` → 本機事件歸檔 `archive/` → R2。從 R2 下載的檔快取在 `pipeline/.cache/`。
- **缺資料的時段**：會略過，執行完會印出幾格、缺幾格。
- **衛星只保留 5 天**（`SAT_KEEP_DAYS`），每天 03:30 會刪掉更舊的。要做 5 天以前的衛星影片，要先在排程電腦從 AWS 補抓，補完**當天**就要做。補抓指令的時間是 UTC，真實色要和 B07、B13 一起補：
  ```bash
  python -m pipeline.fetch_satellite --start 202610211600 --end 202610241200 --bands B07,B13,TC
  ```
- **雷達、測站**：保留 10 天（`KEEP_DAYS`）。更早的事件用 `event_archive` 存下來後，影片會自動從 `archive/` 讀。
- **在前景執行**：MP4 寫檔要在前景執行；在背景執行時，ffmpeg 會出現 WinError 6。三天的影片約 5 分鐘。
- **一次做齊整個事件**：所有影片加 YouTube 說明，用上面的 `event_report`。
